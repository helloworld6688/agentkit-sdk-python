## 云端 Registry CRUD 调用说明

`agentkit uni-reg registry` 操作的是火山引擎控制面的 UniRegistry 实例。它和
`agentkit uni-reg registry binding` 不同：后者只保存本机到数据面的连接信息，不能把
binding 中的 `registry_id` 当作控制面实例 ID 使用。

以下示例使用预发布服务名 `agentkit_stg`。请将尖括号中的值替换为当前账号实际拥有的资源。

### 1. 创建 Registry

```bash
export UNI_REGISTRY_REGION="cn-beijing"
export UNI_REGISTRY_SERVICE="agentkit_stg"
export VPC_ID="<vpc-id>"
export SUBNET_ID="<subnet-id>"
export PROJECT_NAME="<project-name>"
export REGISTRY_NAME="cli-registry-crud-$(date +%s)"

agentkit uni-reg \
  --region "$UNI_REGISTRY_REGION" \
  --service "$UNI_REGISTRY_SERVICE" \
  registry create \
  --name "$REGISTRY_NAME" \
  --replicas 1 \
  --network-spec "{\"vpc_id\":\"$VPC_ID\",\"subnet_ids\":[\"$SUBNET_ID\"]}" \
  --project-name "$PROJECT_NAME" \
  --tag purpose=cli-crud-test
```

说明：

- `--name`：临时实例名称，建议带时间戳，便于清理。
- `--replicas`：实例副本数，测试使用 `1`。
- `--network-spec`：控制面必填的网络配置，必须使用当前账号有权限访问的 VPC 和子网。
- `--project-name`：实例所属项目；是否必填以服务端配置为准。
- 创建成功后，从响应中的 `Result.UniRegistry.Id` 记录控制面 Registry ID：

```bash
export REGISTRY_ID="<Result.UniRegistry.Id>"
```

### 2. 查询单个 Registry

```bash
agentkit uni-reg \
  --region "$UNI_REGISTRY_REGION" \
  --service "$UNI_REGISTRY_SERVICE" \
  registry get "$REGISTRY_ID"
```

该命令调用 `GetUniRegistry`。返回中应包含实例状态及 `PrivateAddress`/`PublicAddress`；
CLI 会将可用的数据面地址缓存到本机配置，供后续 Record 和 SearchSet 命令使用。

### 3. 列表查询 Registry

```bash
agentkit uni-reg \
  --region "$UNI_REGISTRY_REGION" \
  --service "$UNI_REGISTRY_SERVICE" \
  registry list \
  --page 1 \
  --page-size 20 \
  --status RUNNING \
  --project-name "$PROJECT_NAME"
```

该命令当前实现调用 `ListUniRegistries`。`--id`、`--status` 和 `--tag-filter` 可以重复指定；
分页从 `--page 1` 开始。

### 4. 更新 Registry

```bash
agentkit uni-reg \
  --region "$UNI_REGISTRY_REGION" \
  --service "$UNI_REGISTRY_SERVICE" \
  registry update "$REGISTRY_ID" \
  --replicas 2 \
  --monitor-spec '{"enabled":true}'
```

该命令调用 `UpdateUniRegistry`，只提交显式传入字段。测试完成前不要更新共享实例；推荐只更新
本次创建的临时实例。

### 5. 删除 Registry

```bash
agentkit uni-reg \
  --region "$UNI_REGISTRY_REGION" \
  --service "$UNI_REGISTRY_SERVICE" \
  registry delete "$REGISTRY_ID"
```

该命令调用 `DeleteUniRegistry`。删除前应先删除该实例中的临时 SearchSet 和 Record，并确认未启用删除保护。

## 真实控制面 CRUD 重试

以下云端 Registry CRUD 命令均通过外部 `agentkit` CLI 执行：

```bash
agentkit uni-reg --region cn-beijing --service agentkit_stg \
  registry create --name "cli-registry-crud-<timestamp>" --replicas 1

agentkit uni-reg --region cn-beijing --service agentkit_stg \
  registry get ur-direct-101126155162

agentkit uni-reg --region cn-beijing --service agentkit_stg \
  registry list --page 1 --page-size 10
```

- `GetUniRegistry` 已被 `agentkit_stg` 服务识别。对本地数据面 binding ID 调用时返回 `404 ResourceNotFound.Id`，说明该 ID 不是当前控制面下的云端 Registry 资源。
- `CreateUniRegistry` 已通过鉴权并进入服务端参数校验，返回 `400 MissingParameter.NetworkSpec`；创建命令还需要有效的 VPC/子网网络配置。
- 因创建未获得 Registry ID，未执行真实控制面的 `update` 和 `delete`，避免猜测资源 ID 或误操作现有实例。
- `ListUniRegistries` 在当前 `agentkit_stg / 2025-10-30` 返回 `InvalidActionOrVersion`；需要服务端确认最终 List Action 或 Version。
- 当前网络无法解析内网 OpenAPI 域名 `open.volcengineapi.byted.org`。

因此，真实控制面资源的 CRUD 未作为通过项。提供有效 `NetworkSpec` 和正确的 List API 契约后，应按 `create -> get -> list -> update -> delete` 顺序使用上述 CLI 命令复测，并在成功创建后立即删除临时实例。

## 公网 Registry 实际请求记录

使用以下参数对 `agentkit_stg` 发起了真实创建请求：

```bash
agentkit uni-reg \
  --region cn-beijing \
  --service agentkit_stg \
  --output json \
  registry create \
  --name "uni-public-demo-cli-<timestamp>" \
  --replicas 1 \
  --deletion-protection-enabled \
  --json '{
    "NetworkSpec": {
      "NetworkType": ["PUBLIC"],
      "EipBandwidth": 1,
      "IpVersion": "IPv4"
    }
  }'
```

创建成功，服务端返回：

```json
{
  "Result": {
    "Id": "uda5upf1d1blnvvhh73l0"
  }
}
```

创建后使用该 ID 发起查询和更新：

```bash
export REGISTRY_ID="uda5upf1d1blnvvhh73l0"

agentkit uni-reg --region cn-beijing --service agentkit_stg \
  registry get "$REGISTRY_ID"

agentkit uni-reg --region cn-beijing --service agentkit_stg \
  registry update "$REGISTRY_ID" \
  --json '{
    "NetworkSpec": {
      "NetworkType": ["PUBLIC"],
      "AclEntries": ["203.0.113.10/32"]
    }
  }'
```

创建后的前 5 分钟内，查询结果为 `Creating`、`ReadyReplicas=0`，创建态不允许更新：

```text
OperationDenied.Illegal state transition:
Cannot perform update operation on a/an Creating instance.
```

约 10 分钟后，该实例变为 `Running`，`ReadyReplicas=1`。再次调用 ACL 更新后，后续
`registry get` 证实 `AclEntries` 已为 `203.0.113.10/32`。但 `UpdateUniRegistry` 本次返回
`400 InvalidParameter: At least one parameter should be different from current spec`，与实际状态
变更不一致，需要服务端确认该 Action 的响应语义。

关闭删除保护的 update 同样返回该 400，实例当前仍为删除保护开启状态。同时，当前
`DeleteUniRegistry` Action 在 `agentkit_stg / 2025-10-30` 返回 `InvalidActionOrVersion`，
因此 CLI 不能执行删除。

**待处理资源**：`uda5upf1d1blnvvhh73l0`。该资源是本次真实创建产生的临时公网实例，
目前处于 `Running` 且开启了删除保护。需要由具备控制台或服务端运维权限的人员关闭删除保护
并删除，或由服务端确认正确的删除 Action/Version 后再通过 CLI 回收。

### 实现注意事项

`CreateUniRegistry` 的成功响应使用 `Result.Id`，而非 `Result.UniRegistry.Id`。CLI 已改为在
本地缓存不可写或实例地址尚未携带 HTTP(S) scheme 时不影响控制面响应输出。Registry 输出中的
`InitialPassword`、API Key 和其他密码/密钥字段均会自动掩码。调用方解析创建结果时应兼容
`Result.Id`，例如：

```bash
export REGISTRY_ID="$(agentkit uni-reg --region cn-beijing \
  --service agentkit_stg --output json registry create ... | jq -r '.Result.Id')"
```

### Record CRUD

`record list` 成功，初始结果为空：

```json
{
  "total_count": 0,
  "items": []
}
```

使用 `--json` 创建临时 MCP Record 成功：

```bash
agentkit uni-reg record create --json '{
  "name": "mcp-cli-flow-1787560450",
  "type": "mcp",
  "record_version": "1.0.0",
  "description": "CLI flow test MCP record",
  "data": {
    "semantic": {
      "triggers": ["cli flow test"],
      "keywords": ["mcp", "cli", "uni-reg"]
    }
  },
  "network_config": {
    "url": "https://example.com/mcp"
  },
  "extensions": {
    "source": "cli-flow-test"
  }
}'
```

服务端返回 Record ID：

```text
7f11068d3c768e2bc89a70f4a3505fcd
```

随后验证：

- `record get` 成功。
- `record update` 成功，`description` 更新为 `CLI flow test MCP record updated`。
- `record list --name-contains mcp-cli-flow-1787560450` 可查到该 Record。
- `record delete` 返回 `{"success": true}`。

本轮发现数据面 API 要求 `data`、`network_config`、`extensions` 实际传输类型为 JSON
字符串。CLI 已调整为：使用 `record --json` 或 `record --json-file` 时，允许这些字段写成
JSON 对象或数组，CLI 自动转换为服务端需要的 JSON 字符串。
