# UniRegistry CLI 体验指南

`agentkit uni-reg` 用于管理 UniRegistry 实例、实例中的 Record，以及 SearchSet 和关联的 MCP Service。本指南按“安装、连接、创建资源、写入 Record、搜索验证、清理”的顺序给出体验步骤。

## 资源链接

- [AgentKit Python SDK 仓库](https://github.com/volcengine/agentkit-sdk-python)
- [PyPI 包](https://pypi.org/project/agentkit-sdk-python/)
- [AgentKit 控制台](https://console.volcengine.com/agentkit/)
- [AgentKit 文档站](https://volcengine.github.io/agentkit-sdk-python/)
- [安装 AgentKit](../1.introduction/2.installation.md)
- [CLI 配置说明](./3.configurations.md)

体验前向服务提供方获取：控制面地址、认证凭据、Region、可用的 VPC/子网、实例 ID，以及 MCP 场景所需的 Toolset ID。请勿在命令行中传递密码、AK 或 SK，命令行可能被记录到 shell 历史。

## 命令结构

```text
agentkit uni-reg [连接选项] registry         <create|get|list|update|delete>
agentkit uni-reg [连接选项] registry binding <bind|get|list|remove>
agentkit uni-reg [连接选项] record     <create|get|list|update|delete>
agentkit uni-reg [连接选项] search-set <create|provision-mcp|get|list|update|delete|search>
```

通用选项：

| 选项 | 说明 |
| --- | --- |
| `--server` | UniRegistry 控制面地址 |
| `--region` | V4 签名 Region |
| `--service` | V4 签名服务名；未传时读取配置，最终默认 `agentkit` |
| `--output` / `-o` | 输出格式：`json`（默认）或 `table` |
| `--username`、`--password` | Basic Auth，仅用于受控调试环境 |

随时用 `--help` 查看当前安装版本的参数：

```bash
agentkit uni-reg --help
agentkit uni-reg registry create --help
agentkit uni-reg registry binding --help
agentkit uni-reg record create --help
agentkit uni-reg search-set create --help
```

## 1. 安装体验版

### 从体验分支安装

适用于 `uni-reg` 功能尚未发布到 PyPI 的场景：

```bash
git clone https://github.com/volcengine/agentkit-sdk-python.git
cd agentkit-sdk-python
git checkout feat/uni-registry-provider

python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .
```

如果体验包由服务提供方以 wheel 交付，安装其指定文件：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install /path/to/agentkit_sdk_python-<version>-py3-none-any.whl
```

验证安装：

```bash
agentkit --version
agentkit uni-reg --help
```

预期会显示 `registry`、`record`、`search-set` 三个命令组。若提示 `No such command 'uni-reg'`，说明 shell 命中了旧版全局 CLI：

```bash
hash -r
which agentkit
./.venv/bin/agentkit uni-reg --help
```

### 从当前代码生成新的 CLI

`agentkit` 命令由 `pyproject.toml` 中的 `project.scripts` 生成，入口为
`agentkit.toolkit.cli.cli:app`。本地代码更新后，可以用开发态安装立即生成新 CLI，也可以构建
wheel 后分发给体验用户。

开发态生成，适合自己本机验证：

```bash
cd agentkit-sdk-python
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e .

hash -r
which agentkit
agentkit uni-reg --help
```

构建 wheel，适合交付给其他体验用户：

```bash
cd agentkit-sdk-python
python -m pip install --upgrade build
python -m build --wheel
ls dist/
```

生成的文件形如：

```text
dist/agentkit_sdk_python-<version>-py3-none-any.whl
```

体验用户安装该 wheel 后会生成新的 `agentkit` 命令：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install /path/to/agentkit_sdk_python-<version>-py3-none-any.whl

agentkit --version
agentkit uni-reg --help
```

如果需要覆盖当前用户的全局 `agentkit`，使用当前 Python 环境重新安装 wheel：

```bash
python3 -m pip install --user --force-reinstall \
  /path/to/agentkit_sdk_python-<version>-py3-none-any.whl

hash -r
which agentkit
agentkit uni-reg --help
```

如果 `which agentkit` 仍指向旧路径，优先直接使用虚拟环境内的 `./.venv/bin/agentkit`，或调整
`PATH`，确保新安装目录排在旧版 CLI 之前。

## 2. 配置控制面连接和认证

### V4 签名认证

推荐先把控制面默认参数写入 `~/.agentkit/config.yaml`，后续命令即可省略重复的
`--server`、`--region` 和 `--service`：

```yaml
volcengine:
  access_key: "<your-access-key>"
  secret_key: "<your-secret-key>"

uni_registry:
  defaults:
    server: "https://open.volcengineapi.com"
    region: "cn-beijing"
    service: "agentkit_stg"
    registry_id: "<default-registry-id>"
```

也可以通过 CLI 写入全局配置：

```bash
agentkit config --global --set volcengine.access_key="<your-access-key>"
agentkit config --global --set volcengine.secret_key="<your-secret-key>"
agentkit config --global --set uni_registry.defaults.server="https://open.volcengineapi.com"
agentkit config --global --set uni_registry.defaults.region="cn-beijing"
agentkit config --global --set uni_registry.defaults.service="agentkit_stg"
agentkit config --global --set uni_registry.defaults.registry_id="<default-registry-id>"
```

配置完成后，可以直接调用：

```bash
agentkit uni-reg registry list --page 1 --page-size 10
agentkit uni-reg registry get "<registry-id>"
agentkit uni-reg record list
```

命令行参数仍可临时覆盖配置文件，例如切换服务名或 Region：

```bash
agentkit uni-reg --region cn-beijing --service agentkit_stg \
  registry list --page 1 --page-size 10
```

如果不想写入配置文件，也可以使用环境变量。以下环境变量只对当前终端生效：

```bash
export UNI_REGISTRY_SERVER_URL="https://<control-plane-host>"
export VOLCENGINE_ACCESS_KEY="<your-access-key>"
export VOLCENGINE_SECRET_KEY="<your-secret-key>"
export UNI_REGISTRY_REGION="cn-beijing"

agentkit uni-reg \
  --server "$UNI_REGISTRY_SERVER_URL" \
  --region "$UNI_REGISTRY_REGION" \
  registry list --page 1 --page-size 10
```

控制面连接参数的优先级为：命令行参数 > 环境变量 > `~/.agentkit/config.yaml` >
SDK 默认 OpenAPI endpoint。Record 和 SearchSet 的 `registry_id` 优先级为：命令行
`--registry-id` > `uni_registry.defaults.registry_id`。AK/SK 建议保存在全局配置中，不要写入脚本或命令历史。

### Basic Auth 认证

仅当控制面明确使用 Basic Auth 时设置环境变量：

```bash
export UNI_REGISTRY_SERVER_URL="https://<control-plane-host>"
export UNI_USERNAME="<username>"
export UNI_PASSWORD="<password>"

agentkit uni-reg --server "$UNI_REGISTRY_SERVER_URL" \
  registry list --page 1 --page-size 10
```

预期返回资源列表或空列表。`401`/`403` 通常表示凭据、项目权限或控制面地址不正确。

## 3. 创建并确认 UniRegistry 实例

`registry` 命令管理云端 UniRegistry 实例，并调用控制面。`registry binding` 仅管理本地缓存的实例连接信息。复杂请求推荐使用 `--json` 或 `--json-file` 一次性传入完整 JSON；命令行字段只用于快速覆盖少数字段。`--network-spec`、`--monitor-spec`、`--metadata`、`--top` 和 `--json` 的值必须是 JSON 对象；`--tag` 采用 `KEY=VALUE` 格式。

### 3.1 创建实例

VPC 和子网必须使用当前环境中已授权的值。以下为示例字段形状，实际参数以服务方控制面契约为准：

```bash
cat > create-registry.json <<'JSON'
{
  "Name": "uni-public-demo",
  "Replicas": 1,
  "DeletionProtectionEnabled": true,
  "NetworkSpec": {
    "NetworkType": ["PUBLIC"],
    "EipBandwidth": 1,
    "IpVersion": "IPv4"
  }
}
JSON

agentkit uni-reg registry create --json-file ./create-registry.json
```

从输出中记录实例 ID：

```bash
export REGISTRY_ID="ur-xxxxxxxx"
```

也可以直接用 `--json` 提交完整请求对象：

```bash
agentkit uni-reg registry create \
  --json '{"Name":"uni-public-demo","Replicas":1,"NetworkSpec":{"NetworkType":["PUBLIC"],"EipBandwidth":1,"IpVersion":"IPv4"}}'
```

### 3.2 确认实例状态与数据面地址

```bash
agentkit uni-reg registry get "$REGISTRY_ID" --output table

agentkit uni-reg registry list --status RUNNING --page 1 --page-size 20 --output table
```

确认结果中存在可访问的 `private_address` 或 `public_address`。`registry create` 和 `registry get` 会将地址缓存到 `~/.agentkit/config.yaml`，供后续数据面命令使用。

如果实例已由他人创建，先执行一次 `registry get`。也可以由管理员手工绑定数据面地址：

```bash
agentkit uni-reg registry binding bind "$REGISTRY_ID" \
  --private-address "https://<private-data-plane-host>" \
  --public-address "https://<public-data-plane-host>"

agentkit uni-reg registry binding get "$REGISTRY_ID"
```

`registry binding get` 会掩码敏感字段。不要将含密码的绑定命令写入脚本。

## 4. 创建并验证 Record

Record 请求实例数据面。已配置 `uni_registry.defaults.registry_id` 时可以省略 `--registry-id`；否则必须显式传入。CLI 优先使用缓存的 `private_address`，连接失败时自动尝试 `public_address`；缓存不存在时会调用控制面 `GetUniRegistry` 获取并缓存地址。

### 4.1 创建 Record

推荐用 `--json-file` 传入完整 Record 请求，避免多个 JSON 字段在 shell 中转义。`data`、`network_config` 和 `extensions` 可以写成 JSON 对象或数组，CLI 会自动转换成数据面 API 需要的 JSON 字符串。也可以继续使用 `--data` 或 `--data-file`；此时二者必须二选一，内容必须为合法 JSON。

```bash
cat > create-record.json <<'JSON'
{
  "name": "crm-export-demo",
  "type": "mcp",
  "record_version": "1.0.0",
  "description": "用于体验流程的 CRM 报表导出服务",
  "data": {
    "semantic": {
      "triggers": ["导出 CRM 报表"],
      "keywords": ["crm", "报表"]
    }
  },
  "network_config": {
    "url": "https://<your-mcp-host>/mcp"
  },
  "extensions": {
    "owner": "demo-team"
  }
}
JSON

agentkit uni-reg record create --json-file ./create-record.json
```

未配置默认 `registry_id` 时，补充 `--registry-id`：

```bash
agentkit uni-reg record create \
  --registry-id "$REGISTRY_ID" \
  --json-file ./create-record.json
```

只传 Record 语义数据时，仍可以使用 `--data-file`：

```json
{
  "semantic": {
    "triggers": ["查询演示数据"],
    "keywords": ["demo", "search"]
  }
}
```

```bash
agentkit uni-reg record create \
  --name "demo-search" \
  --type "mcp" \
  --record-version "1.0.0" \
  --data-file ./record-data.json
```

记录创建结果中的 Record ID：

```bash
export RECORD_ID="record-xxxxxxxx"
```

### 4.2 查询和更新

```bash
agentkit uni-reg record get "$RECORD_ID"

agentkit uni-reg record list \
  --page 1 --page-size 20 \
  --name-contains crm \
  --type mcp

agentkit uni-reg record update "$RECORD_ID" \
  --json '{"description":"更新后的演示描述","status":"RUNNING"}'
```

`record update` 只修改显式传入字段。`--data`、`--network-config` 和 `--extensions` 传入时均应为合法 JSON；使用 `--json` 或 `--json-file` 时，这些字段可以直接写成 JSON 对象或数组，由 CLI 自动转换。

## 5. 创建 SearchSet 并验证搜索

SearchSet 将多个 Record 组成独立搜索集合。创建和更新必须提交该集合完整的成员列表；字段较多时推荐使用 `--json` 或 `--json-file`。

```bash
export SEARCH_SET_NAME="demo-search-set"

cat > create-search-set.json <<'JSON'
{
  "name": "demo-search-set",
  "description": "CLI 体验搜索集合",
  "resource_ids": ["record-xxxxxxxx"],
  "search_config": {
    "max_results": 10,
    "min_score": 0.3
  }
}
JSON

agentkit uni-reg search-set create --json-file ./create-search-set.json
```

已配置 `uni_registry.defaults.registry_id` 时，SearchSet 请求默认实例的数据面；未配置时可通过
`--registry-id` 指定实例。

```bash
agentkit uni-reg search-set get "$SEARCH_SET_NAME"

agentkit uni-reg search-set search "$SEARCH_SET_NAME" "导出 CRM 报表"

agentkit uni-reg search-set list \
  --page 1 --page-size 20
```

`search` 只在指定集合成员内检索，调用的数据面接口为：

```text
POST /api/v1/search-sets/{name}/search
```

更新集合会替换成员列表：

```bash
agentkit uni-reg search-set update "$SEARCH_SET_NAME" \
  --json '{"resource_ids":["record-xxxxxxxx"],"search_config":{"max_results":20,"min_score":0.2}}'
```

## 6. 可选：创建 MCP Service 并等待 Ready

此流程需要已准备的 MCP 后端、MCP Service 请求参数和服务方提供的 `MCPToolsetId`。CLI 依次创建 SearchSet、调用 `CreateMCPService`，再轮询 `GetMCPService` 和 `GetMCPToolset`，直到状态为 `Ready`、失败或超时。

将 MCP Service 请求放入文件。文件可能含 API Key，不要提交到 Git：

```json
{
  "Name": "mcp-demo-search",
  "Path": "/mcp",
  "ProtocolType": "MCP",
  "NetworkConfigurations": [{"NetworkType": "Public"}],
  "BackendType": "Function",
  "BackendConfiguration": {
    "FunctionConfiguration": {"FunctionId": "<function-id>"}
  },
  "GatewayMode": "Shared"
}
```

```bash
MCP_SERVICE_JSON="$(< ./mcp-service.json)"
export MCP_TOOLSET_ID="mt-xxxxxxxx"

agentkit uni-reg search-set create \
  --name "demo-mcp-search-set" \
  --resource-id "$RECORD_ID" \
  --mcp-service-json "$MCP_SERVICE_JSON" \
  --mcp-toolset-id "$MCP_TOOLSET_ID" \
  --wait-interval 3 \
  --wait-timeout 180
```

若 SearchSet 已创建，只编排 MCP：

```bash
agentkit uni-reg search-set provision-mcp "demo-mcp-search-set" \
  --mcp-service-json "$MCP_SERVICE_JSON" \
  --mcp-toolset-id "$MCP_TOOLSET_ID" \
  --wait-interval 3 \
  --wait-timeout 180
```

MCP Service 是独立云资源，删除 SearchSet 不等价于回收 MCP Service，应遵循服务方规定的回收方式。

## 7. 清理体验资源

按依赖反向顺序清理：

```bash
agentkit uni-reg search-set delete "$SEARCH_SET_NAME"

agentkit uni-reg record delete "$RECORD_ID"

agentkit uni-reg registry delete "$REGISTRY_ID"

agentkit uni-reg registry binding remove "$REGISTRY_ID"
```

删除前确认资源未被其他体验者共享；启用删除保护的实例需先按控制面策略解除保护。

## 常见问题

| 现象 | 排查方式 |
| --- | --- |
| `No such command 'uni-reg'` | 执行 `which agentkit`，确认虚拟环境中的体验版 CLI 生效。 |
| `Volcengine credentials are required` | 设置 AK/SK，或通过 `agentkit config --global` 保存凭据。 |
| `401` / `403` | 检查认证方式、凭据、资源权限和控制面地址。 |
| 无 `private_address` / `public_address` | 执行 `registry get "$REGISTRY_ID"`，确认实例就绪且返回有效 HTTP(S) 地址。 |
| 私网请求失败 | 确认本机到 VPC 的连通性；CLI 会在连接类错误时回退到公网地址。 |
| `--data must contain valid JSON` | 使用 `jq . record-data.json` 验证文件，或改用 `--data-file`。 |
| MCP 等待超时 | 确认 MCP 后端、Toolset ID 和权限，必要时增大 `--wait-timeout`。 |

## 流程检查表

```text
1. 安装带 uni-reg 功能的体验版 agentkit。
2. 配置控制面地址、认证和默认 registry-id，使用 registry list 验证连通性。
3. 创建或查询实例，确认 registry-id 和数据面地址已写入本地配置。
4. 使用 --json-file 创建 Record，记录 record-id，并使用 record get 验证。
5. 使用 --json-file 创建 SearchSet，使用 search-set search 验证集合搜索。
6. 可选：创建 MCP Service，等待 Toolset Ready。
7. 按 SearchSet、Record、实例的顺序清理体验资源。
```
