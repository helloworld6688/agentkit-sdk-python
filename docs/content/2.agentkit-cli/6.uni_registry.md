# UniRegistry 与 SearchSet CLI

`agentkit uni-reg` 管理 UniRegistry 控制面资源、实例中的 Record，以及
SearchSet。命令结构如下：

```text
agentkit uni-reg resource   <create|get|list|update|delete>
agentkit uni-reg record     <create|get|list|update|delete>
agentkit uni-reg search-set <create|get|list|update|delete|search>
```

## 本地启动 CLI

CLI 是一个本地命令行进程，不会启动 UniRegistry 服务。先在
`uni-registry` 项目中启动控制面和实例数据面，再在本仓库安装并调用 CLI。

本项目要求 Python 3.10 以上；本地开发建议使用仓库指定的 Python 3.12：

```bash
cd /Users/bytedance/project/bytedance/uni-reg/agentkit-sdk-python

uv venv --python 3.12
source .venv/bin/activate
uv sync
uv pip install -e .

agentkit uni-reg --help
```

若提示 `No such command 'uni-reg'`，当前 shell 命中了全局安装的旧版
`agentkit`。重新激活本项目环境并刷新 shell 的命令缓存：

```bash
cd /Users/bytedance/project/bytedance/uni-reg/agentkit-sdk-python
source .venv-agentkit/bin/activate
hash -r

which agentkit
agentkit uni-reg --help
```

`which agentkit` 应输出：

```text
/Users/bytedance/project/bytedance/uni-reg/agentkit-sdk-python/.venv-agentkit/bin/agentkit
```

也可绕过 `PATH`，直接运行项目内的 CLI：

```bash
./.venv-agentkit/bin/agentkit uni-reg --help
```

如果不需要安装 console script，也可以从源码直接运行：

```bash
source .venv/bin/activate
PYTHONPATH="$PWD" python -m agentkit.toolkit.cli.cli uni-reg --help
```

控制面在本地运行时，将其地址传给 `--server`：

```bash
agentkit uni-reg --server http://localhost:8888 resource list
```

Record 命令会继续根据 `--registry-id` 查询实例地址，优先使用
`private_address`；私网地址网络不可达时再 fallback 到 `public_address`。本地
环境中，至少一个地址必须能被 CLI 进程访问；例如可解析为
`http://localhost:<port>`。

## 连接配置

`--server` 是 UniRegistry 控制面地址。可以每次显式传入，也可以设置环境变量：

```bash
export UNI_REGISTRY_SERVER_URL="https://control.example.com"
export UNI_REGISTRY_REGION="cn-beijing"
```

控制面使用 Basic Auth 时：

```bash
export UNI_USERNAME="your-username"
export UNI_PASSWORD="your-password"
```

未设置 Basic Auth 时，CLI 使用 AgentKit 凭据链和 Volcengine V4 签名。默认
签名 service 为 `agentkit`；可用 `--service` 覆盖。所有命令可附加
`--output table` 以表格形式打印结果。

## Record 调用规则

Record 不直接请求控制面。每次 Record CRUD 都必须传入 `--registry-id`，CLI
会执行以下步骤：

```text
GetUniRegistry(registry-id)
-> registry.private_address
-> 私网地址的 /api/v1/records
-> 私网不可达时 fallback 到 registry.public_address
```

因此，`registry-id` 是实例发现参数，而不是 Record API 的查询条件。实例必须
返回带 `http://` 或 `https://` 的 `private_address` 或 `public_address`。

### 创建 Record

`--data` 和 `--data-file` 二选一。`data`、`network-config`、`extensions` 都是
JSON 字符串。

```bash
agentkit uni-reg --server "$UNI_REGISTRY_SERVER_URL" \
  record create \
  --registry-id ur-xxxxxxxx \
  --name crm-export \
  --type mcp \
  --record-version 1.0.0 \
  --description "CRM 报表导出 MCP 服务" \
  --data '{"semantic":{"triggers":["导出 CRM 报表"],"keywords":["crm","报表"]}}' \
  --network-config '{"url":"https://mcp.example.com/mcp"}' \
  --extensions '{"owner":"sales"}'
```

长 JSON 可以使用文件：

```bash
agentkit uni-reg record create \
  --registry-id ur-xxxxxxxx \
  --name crm-export \
  --type mcp \
  --record-version 1.0.0 \
  --data-file ./record-data.json
```

### 查询、列表、更新、删除 Record

```bash
agentkit uni-reg record get record-xxxxxxxx \
  --registry-id ur-xxxxxxxx

agentkit uni-reg record list \
  --registry-id ur-xxxxxxxx \
  --page 1 \
  --page-size 20 \
  --name-contains crm \
  --type mcp \
  --status RUNNING

agentkit uni-reg record update record-xxxxxxxx \
  --registry-id ur-xxxxxxxx \
  --description "更新后的描述" \
  --status RUNNING \
  --data '{"semantic":{"keywords":["crm","report"]}}'

agentkit uni-reg record delete record-xxxxxxxx \
  --registry-id ur-xxxxxxxx
```

## UniRegistry 资源管理

`resource` 命令直接调用控制面 RPC，不需要 `--registry-id`。

```bash
agentkit uni-reg resource create \
  --name registry-prod \
  --replicas 2 \
  --network-spec '{"vpc_id":"vpc-xxx","subnet_ids":["subnet-xxx"]}' \
  --project-name default \
  --tag environment=production

agentkit uni-reg resource get ur-xxxxxxxx

agentkit uni-reg resource list \
  --page 1 \
  --page-size 20 \
  --status RUNNING \
  --project-name default

agentkit uni-reg resource update ur-xxxxxxxx \
  --replicas 3 \
  --monitor-spec '{"enabled":true}'

agentkit uni-reg resource delete ur-xxxxxxxx
```

支持的 `resource` JSON 参数：

| 命令 | JSON 参数 |
| --- | --- |
| `create` | `--network-spec`、`--monitor-spec`、`--metadata`、`--top`、`--json` |
| `get` | `--top` |
| `list` | `--top`、`--tag-filter` |
| `update` | `--network-spec`、`--monitor-spec`、`--metadata`、`--top`、`--json` |
| `delete` | `--top` |

## SearchSet 管理

SearchSet 的 CRUD 和搜索都请求控制面。`--resource-id` 是已有 Record 的 ID；
创建或更新时必须传完整的成员列表。

```bash
agentkit uni-reg search-set create \
  --name finance \
  --description "财务资源搜索集" \
  --resource-id record-1 \
  --resource-id record-2 \
  --search-config '{"max_results":10,"min_score":0.3,"debug":true}'

agentkit uni-reg search-set get finance

agentkit uni-reg search-set list --page 1 --page-size 20

agentkit uni-reg search-set update finance \
  --resource-id record-1 \
  --resource-id record-3 \
  --search-config '{"max_results":20,"min_score":0.2}'

agentkit uni-reg search-set search finance "导出财务报表"

agentkit uni-reg search-set delete finance
```

`search-set search` 使用：

```http
POST /api/v1/search-sets/{name}/search
```

因此结果仅来自该 SearchSet 的成员，不是全局 Record 搜索。

## 创建 SearchSet 后编排 MCP

在 `search-set create` 中传入 `--mcp-service-json` 时，CLI 会先创建
SearchSet，再调用：

```text
POST /?Action=CreateMCPService&Version=2025-10-30
POST /?Action=GetMCPToolset&Version=2025-10-30
```

将 MCP Service 请求保存为 `mcp-service.json`：

```json
{
  "Name": "mcp-finance",
  "Path": "/mcp",
  "ProtocolType": "MCP",
  "NetworkConfigurations": [
    {
      "NetworkType": "Public"
    }
  ],
  "BackendType": "Function",
  "BackendConfiguration": {
    "FunctionConfiguration": {
      "FunctionId": "26fqb4gn"
    }
  },
  "InboundAuthorizerConfiguration": {
    "AuthorizerType": "ApiKey",
    "Authorizer": {
      "KeyAuth": {
        "ApiKeys": [
          {
            "Name": "apikey-finance-in"
          }
        ],
        "ApiKeyLocation": "HEADER"
      }
    }
  },
  "OutboundAuthorizerConfiguration": {
    "AuthorizerType": "ApiKey",
    "Authorizer": {
      "KeyAuth": {
        "ApiKeys": [
          {
            "Name": "apikey-finance-out",
            "Key": "usix-sixa-xxxx-xxx"
          }
        ],
        "ApiKeyLocation": "HEADER"
      }
    }
  },
  "GatewayMode": "Shared"
}
```

然后执行：

```bash
MCP_SERVICE_JSON="$(cat ./mcp-service.json)"

agentkit uni-reg search-set create \
  --name finance \
  --resource-id record-1 \
  --resource-id record-2 \
  --mcp-service-json "$MCP_SERVICE_JSON" \
  --mcp-toolset-id mt-yesy5smk8wdcxee5qo4q \
  --wait-interval 3 \
  --wait-timeout 180
```

`CreateMCPService` 是异步服务创建接口。CLI 会轮询指定 Toolset，直到状态为
`Ready`，并输出 Toolset 的公网 endpoint、API Key 和关联 MCP Service 信息。

`CreateMCPService` 返回 `MCPServiceId`，不会返回 `MCPToolsetId`。因此当前
CLI 必须由 `--mcp-toolset-id` 提供 Toolset ID，除非将来的 SearchSet API 响应
增加 `mcp_toolset_id` 字段。

## 完整流程

```text
1. 创建或查询 UniRegistry 资源，得到 registry-id。
2. 用 registry-id 创建多个 Record。
3. 用这些 Record ID 创建 SearchSet。
4. SearchSet 创建后提交 CreateMCPService。
5. 使用 MCPToolsetId 轮询 GetMCPToolset，直到 Ready。
6. 使用 search-set search 验证集合内搜索结果。
```
